# ADR-0001: Сповіщення та повернення посилок за часом прибуття

**Статус:** запропоновано  
**Дата:** 2026-11-09

## Context

Зараз `POST /parcels` реєструє посилку зі статусом `waiting` і часом `arrivedAt`. Воркер надсилає одне SMS про прибуття, а нічна задача повертає посилки, старші за 72 години. Код отримання в реалізації шестизначний. Поточна нічна задача не забезпечує повернення в момент завершення 72 годин; операції отримання й повернення також потребують захисту від одночасного виконання.

**Припущення:** час прибуття фіксує сервер у UTC; 24, 48 і 72 години відраховуються від нього, незалежно від часу доставки SMS. «Статус повернення» для відправника може показувати окремо *повернення розпочато* та *повернено*. Фізично звільнити зайняту комірку можна лише після підтвердження вилучення посилки кур’єром або обладнанням.

## Decision

Зберігати в PostgreSQL посилку та заплановані дії для неї. Під час реєстрації в одній транзакції створювати посилку й чотири записи з `due_at`: SMS про прибуття, нагадування через 24 години, нагадування через 48 годин і початок повернення через 72 години. Воркер вибирає належні до виконання записи з блокуванням рядків, повторює невдалі дії та веде стан кожної дії. Записи мають унікальний ключ `(parcel_id, action_type)`, щоб повторний запуск не створював нових нагадувань.

Перед кожним SMS воркер перевіряє, що посилка ще очікує отримання. SMS містить номер поштомата й код; номер телефону та код не потрапляють до звичайних журналів. Для захисту від дублювання після збою використовується ключ ідемпотентності SMS-провайдера, **якщо він його підтримує**. Без такої підтримки можливе повторне SMS після успішної відправки, яку воркер не встиг записати.

Правило 72 годин застосовується безпосередньо в транзакції отримання: після `arrived_at + 72 години` код уже не може завершити `pickup`, навіть якщо воркер запізнився. У момент досягнення строку система переводить посилку в `returning`, робить цей стан доступним відправнику та запитує повернення через API кур’єра з ідемпотентним ідентифікатором. Статус `returned` і комірка `available` встановлюються атомарно **після підтвердження фізичного вилучення**. Потрібен окремий захищений спосіб для відправника переглядати статус своєї посилки; наявний `/admin/parcels` призначений персоналу.

Таким чином, **рівно через 72 години** завершується право на отримання й починається повернення. Існуючий API кур’єра лише приймає запит на повернення: він не дає змоги гарантувати фізичне вилучення та звільнення комірки саме в цю мить. Для буквального виконання цієї частини вимоги потрібні інтеграція з обладнанням або підтверджена домовленість із кур’єром про виконання в заданий час.

### Розглянуті альтернативи

| Варіант | Переваги | Компроміси |
|---|---|---|
| Розширити наявний воркер і зберігати заплановані дії в PostgreSQL — **обрано** | Використовує наявні БД і воркер; дії переживають перезапуск; простіше контролювати одночасні операції | Зовнішні дії можуть початися пізніше `due_at` через інтервал опитування, збій або навантаження |
| Окремі таймери в процесі Node.js для кожної посилки | Мало змін у схемі даних; запуск близько до потрібного часу за нормальної роботи | Таймери губляться при перезапуску, складно узгодити кілька екземплярів; неприйнятно для повернення |
| Зовнішня черга із відкладеними повідомленнями | Масштабує виконання й зменшує потребу опитувати БД | Додає інфраструктуру й вартість; доставка повідомлення все одно не гарантує виконання зовнішньої дії рівно за розкладом; стан посилки залишається в БД |

## Consequences

Потрібні міграція БД, зміни воркера й атомарні переходи стану для отримання та повернення. Нічну задачу варто залишити як механізм звірки й відновлення пропущених дій, а не як основний спосіб повернення. Слід відстежувати затримку від `due_at` до виконання, невдалі SMS та запити кур’єру, а також посилки, що довго залишаються в `returning`.

Відправник побачить початок повернення після закінчення 72 годин і підтверджене повернення після вилучення. Обіцяти звільнення фізично зайнятої комірки рівно на позначці 72 години за наявним контрактом із кур’єром було б некоректно.
